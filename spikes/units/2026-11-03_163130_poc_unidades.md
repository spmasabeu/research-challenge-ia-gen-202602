## Ajuste del parser

El parser inicial exigía `FINAL:`. Las 30 respuestas lo omitieron: el resultado original fue 0/30 por formato. Se conservan `summary.json` y `responses.jsonl` originales.

El parser actual acepta también un único objeto JSON en la última línea. Se reevaluaron las mismas respuestas sin nuevas llamadas al modelo. Los resultados utilizables están en `rescored.json`, con respuestas, referencias y hash del script actualizado. El hash en `metadata.json` corresponde al script anterior al ajuste. Generador y prompts no cambiaron.

Verificar puntuaciones guardadas sin inferencia:

```bash
uv run --no-project --isolated --python 3.12 python - <<'PY'
import json
from pathlib import Path
from poc_units import verify

folder = Path("results/2026-11-03")
tasks = {t["id"]: t for t in map(json.loads, (folder / "tasks.jsonl").read_text().splitlines())}
results = json.loads((folder / "rescored.json").read_text())["results"]
for result in results:
    assert verify(tasks[result["id"]], result["completion"]) == result["status"]
print("30 puntuaciones verificadas")
PY
```

## Límites

Muestra pequeña, plantillas repetidas, una respuesta por problema. Los niveles combinan familias distintas y no aíslan causalmente el efecto de las conversiones. Sin splits finales, pass@k, SFT/DPO ni entrenamiento.

Catálogo y parser para piloto, sin endurecimiento contra ataques. Se puntúa la respuesta final, no la corrección de los pasos; el 1% puede aceptar cálculos ligeramente incorrectos.

Siguiente paso: repetir con el modo de razonamiento elegido para el proyecto y ampliar la muestra por familia. Modo, cuantización y presupuesto pueden cambiar los resultados.
